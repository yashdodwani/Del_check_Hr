## 6. Failures found and improvements made

Chronological milestones (details, numbers and root causes are in `log.txt`):

* Milestone 1 — Repository & environment inspection
* Milestone 2 — Evidence study, parsers & extraction scaffolding
* Milestone 3 — Audit engine, identity resolution, workflow attribution, scorer
* Milestone 4 — Per-request scoping, attachment/replica categories, tie-breaks
* Milestone 5 — Intent classifier, pipeline entry point, first full run
* Milestone 6 — Synthetic regression dataset (10 scenarios) and OCR fixes
* Milestone 7 — Automated regression tests
* Milestone 8 — Evaluation runner, reports, README, packaging, final run

Key failure → fix pairs:

* Identifier-less records (404 account lookups, anonymised analytics) were unlinkable → added workflow attribution; sample sequence accuracy 0.25 → 0.78.
* One person with two requests received each other's records → per-request partitioning by time.
* Support PDF treated as a conversation (REDACT) instead of an attachment (DELETE) → document-type cue.
* Replica contact copies treated as support messages → SECONDARY_IDENTIFIER (DELETE).
* Readback exports were treated as full snapshots, wrongly implying absence of retained audit records → only bundles/SQL dumps imply absence, never for RETAIN categories.
* Small-text screenshot misread (`backup.00001`, dot-less email domain) and not flagged → 3x OCR variant, malformed-id/broken-email detection, row-level restore status (synthetic S09).

## 7. Known limitations

* The attribution step relies on timing regularities of the deletion workflow; when several same-status requests report at the same time and have no other linked records, the assignment can be wrong (see §4).
* The vision fallback (`nvidia/nemotron-3-nano-omni-30b-a3b-reasoning`) is only called with an NVIDIA_API_KEY; without it, layout-sensitive screenshots rely on Tesseract plus identifier validation and are flagged `needs_vision` in the extraction cache.
* Records that never appear in participant data cannot be reported.
